# 三个群聊玩梗摊位设计

**日期：** 2026-09-03

## 目标

为华府后街三个筹备中摊位设计首期玩法。目标不是提供严肃职场工具，而是产出适合同事群转发、接梗和轻度吐槽的群体道具卡。

三者共同覆盖一个职场叙事：新人入府、会议逃生、年终表彰。每次体验由一人发起，但结果明确邀请群里的其他人继续补充或投票。

## 产品原则

- 单人发起、群聊接力；不需要账号、房间、邀请或实时协作。
- 轻度吐槽工作流程、会议和组织语言，不评价具体同事、领导或公司。
- 每个结果都同时提供视觉卡片、可复制的群聊文本和一句接梗引子。
- 用户只填一到两个轻输入；生成后可重办、复制或保存 PNG。
- 模型故障时使用本地预置结果，不能让摊位冷场。

## 摊位设计

### A-03 入府适应办：华府新员工说明书

用户输入同事昵称（可留空）和部门类型。系统生成一份一本正经的“新员工入府注意事项”。

输出栏目：

- 入职首日必修课
- 生存装备
- 直属领导饲养指南（仅描述泛化的工作习惯）
- 三条隐藏条例
- 群聊引子：`请各位老员工补充本员工尚未掌握的隐藏条例。`

卡片视觉为复古规章页或员工手册。结果文本不包含用户输入的完整昵称；可在分享卡上使用“新员工”代称以降低定向感。

### C-04 会议脱身处：会议逃生演练

用户选择会议类型和脱身程度（正常、紧急、荒诞）。系统生成一份会议突发事件演练通报。

输出栏目：

- 突发事件
- 当前逃生身份
- 三步逃生动作
- 预计成功率
- 群聊引子：`请投票：这套方案能否在“最后补充一点”前成功离场？`

卡片视觉为企业安全演练通报。荒诞感来自流程语言与无害事故设定，不涉及伪造病假、冒充真人或规避真实工作责任。

### D-02 绩效申辩堂：年度摸鱼成果展

用户填写一件看似无效的小事并选择工作类型。系统将它授予荒诞但不攻击人的年度成果奖。

输出栏目：

- 奖项名称
- 表彰事由
- 可量化的虚构成果
- 评审委员会批语
- 群聊引子：`请各位同事提交自己的年度获奖项目。`

卡片视觉为红头表彰文件。它避免将摸鱼包装成真实绩效建议；内容是戏仿而非用于正式工作材料。

## 共用体验与数据流

1. 用户填写一到两个字段并提交。
2. 通用 AI 摊位框架读取该摊位的专属字段配置、系统提示词和输出栏目。
3. 服务端验证输入、生成结构化结果，并过滤定向侮辱、歧视或对真实人物的攻击。
4. 结果页渲染主题卡片、群聊文本版、接梗引子和重办入口。
5. 成功生成后记录匿名日受理数；用户保存图片时沿用既有匿名保存统计。
6. 若模型不可用、超时或输出不合格，返回本地预置的同主题结果，同时保持复制与保存能力。

## 实现边界

- 复用 `generic_ai` 摊位类型和既有生成接口；三个现有 `coming_soon` 配置上线时改为 `open`。
- 为三个摊位分别配置字段、提示词、结果 schema、群聊文本模板和卡片主题。
- 图片继续使用既有 Canvas 分享能力，分别实现规章页、演练通报和红头表彰三种模板。
- 不增加用户账户、内容持久化、多人房间、实时同步或群平台集成。

## 内容安全与失败处理

- 输入中出现具体真实对象时，输出仍只描述泛化职场情境，不生成攻击、羞辱、造谣或歧视内容。
- 不提供欺骗性脱身方案、伪造证明或规避工作责任的具体指令。
- 对无效输入给出幽默但中性的重新引导。
- 模型失败或超时不暴露技术细节，展示“本摊临时改由人工印刷”的本地兜底卡，并支持重试。

## 验收标准

- 三个摊位各自只需一到两个输入即可完成一次体验。
- 每次结果有主题卡片、可复制群聊文本和明确的群聊接梗引子。
- 移动端和桌面均可稳定保存 PNG；图片不可用时文本结果仍可复制。
- 定向攻击、歧视和危险脱身建议不会出现在生成结果中。
- 模型失败时三个摊位均能展示可分享的本地兜底结果。
- 成功生成和图片保存沿用匿名统计，不保存用户业务文本。

## 测试范围

- 三个摊位的字段校验与结构化结果解析。
- 主题提示词、群聊引子和文本模板的选择。
- 有害或定向吐槽输入的拒绝、改写与安全降级。
- 模型异常、超时和结构化输出错误时的本地兜底。
- 三个 Canvas 卡片模板的关键文案与导出调用。
